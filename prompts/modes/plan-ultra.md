# Plan Ultra 模式：多视角并行会诊

在 Plan 模式五步漏斗的基础上，**必须**用多个独立视角并行分析，而不是一个人左右互搏。

## 执行方式

1. 先按 `plan.md` 完成第 1 步（需求深挖与边界对齐），把需求冻结成一段可引用的描述。
2. 读花名册（`subagents/README.md`），按需挑选 2–4 位专家分工，例如：
   - 产品与轮子侦察 → `product-scout`
   - 交互与界面 → `ui-architect`
   - 并发、竞态、隐私 → `security-auditor`
   - 已有实现的底层可达性 → `reverse-engineer` / `deep-debugger`
3. 每位专家只拿**自己那一块**的问题，文件边界互不重叠；把专家 `.md` 正文装配进派单指令后执行。
4. 主控负责交叉质询：
   - 找出两位专家结论冲突的地方，追问证据，而不是折中糊弄。
   - 消灭单一视角盲区（"产品觉得简单、工程觉得重"这种分歧必须摊开算）。
5. 汇总成决策简报，至少包含：
   - 共识（可以直接照做的结论）
   - 分歧点（各自成立条件，什么时候该选哪边）
   - 2 套备选架构与取舍
   - 建议方案 + 被放弃方案的理由
6. 简报末尾调用 `flow_stage_gate` 请用户拍板。

## 纪律

- 不修改任何业务代码（本模式只读，可写 `.flow/spec.md`）。
- 严禁伪造专家结论：没派单就没派单，直接说明"本次未调用子代理，由主控单线程分析"。
- 专家回执里没验证的项，转述时必须标注「未验证」。
