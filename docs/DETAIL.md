# Flow 工作流与提示词管家

给 DSH 加五个快捷工作流模式，并把提示词分三层注入；v0.5.0 起再叠一层**工程级 SOP 编排**（分级、编号文档、可遥控门禁、派单白名单、双阶验收）。

## 它能做什么

聊天输入区「开发权限」芯片右侧会多出一个 `Flow` 芯片，点开是六个选项：
`普通模式（off）`、`Plan`、`Plan Ultra`、`Build`、`Review`、`Flow`。

选中某个模式时，插件做三件事，而且**只在切换的那一刻各做一次**：

1. 若该模式配置了默认模型，切换当前会话的模型（可用 `provider::model` 指定）；
2. 应用该模式的权限档位（只读 / 工作区修改 / 完全权限 / 不修改）；
3. 从下一个模型步骤起注入该模式的提示词。

之后你在对话框里手动换模型、手动换权限都**不会被插件改回去**——插件不再参与。

## 三层提示词

| 层 | 放哪 | 是否随模式变化 |
|---|---|---|
| 底座契约 | 系统提示词最前部（固定位置） | 否 |
| 全局提示词（可多套，逐模式勾选） | 运行时上下文（追加在对话末尾） | 是 |
| 模式专属提示词 | 同上，排在全局提示词之后 | 是 |

底座契约永远不动，所以系统提示词的前缀缓存能长期命中；随模式变化的内容全部走
运行时上下文，不会改写系统提示词本体。

拼接顺序是「勾选的全局提示词（按配置顺序）→ 模式专属提示词」，模式硬规则压在人设之后。

## 配置方式

**设置 → Flow 工作流**（左侧设置导航），两个区块：

- **全局提示词**：多套管理，每套可启用/停用、改名、改正文，并为五个模式分别勾选是否生效。
- **五大模式**：每个模式一个默认模型（首项「不自动切换」）、一个切换时权限档位、
  一段模式专属提示词，以及「恢复默认」。

所有修改逐字段写入，不清空你没动过的部分；「恢复默认」是撤回该字段的覆盖值，
回落到插件内置默认，不是把你当前文本清空。

## 写入口

模式切换只有一个写入口：`/flow <mode>` 命令。

- 在输入框手动敲 `/flow plan` 效果和点芯片完全一样；
- `/flow status` 或 `/flow` 只回报当前模式；
- 拼错的模式名会被拒绝，不会改变当前状态。

每次切换会在对话里留一条命令行记录，这与原生 `/permission` 芯片的行为一致，
是有意保留的可审计轨迹。

## 命令总览（v0.5.0）

`/flow` 后面的**第一个 token** 决定走哪条子命令。下表与 `commands.js` 的真实实现一一对应：

| 命令 | 作用 | 备注 |
|---|---|---|
| `/flow <mode>` | 切换模式 `off` / `plan` / `plan-ultra` / `build` / `review` / `flow` | 与点芯片等价，留审计轨迹 |
| `/flow` 或 `/flow status` | 回报当前模式与可选项 | 不改状态 |
| `/flow spec` | 看 `.flow/spec.md` 锚点摘要与大小 | 文件不存在时如实说明 |
| `/flow compact` | 手动触发一次上下文压缩 | 走压缩桥，失败有回执 |
| `/flow prompts list` | 列出提示词版本、五模式来源、特种兵清单 | 只读 |
| `/flow prompts update` | 拉远端提示词库并逐文件校验 sha256 | 不覆盖 `prompts/custom/` |
| `/flow gate list` | 列出当前会话的门禁票据（状态 / 选项 / 是否 hold） | 卡片消失后仍可查 |
| `/flow gate answer <票据> <1\|2\|3> [附带意见]` | 结算一张票据；附带意见会原样传给桌面会话 | 与 IM 回 `#票据号 1 意见` 等价 |
| `/flow gate skip <票据> [附带意见]` | 跳过（等价于选第 2 项） | 跳过项要写进未验证清单 |
| `/flow gate doc <票据>` | 看该票据关联文档或未落盘草稿的摘要 | 长文按 `gate.docDigestChars` 截断 |
| `/flow gate release <票据>` | 解除超时后的 hold，**但仍等你决定**，不会自动推进 | 用于"再想想" |
| `/flow docs init` | 按当前等级生成缺失的文档骨架 | 只写模板，无需授权 |
| `/flow docs`（也可写 `/flow docs list`） | 逐份校验全部必做文档，缺章节会点名 | 默认子命令就是校验 |
| `/flow docs 05` | 只校验指定编号 | 传编号即单份模式 |
| `/flow retry` / `/flow escalate` / `/flow resume` | 熔断三件套：重试 / 换救场模型重试 / 解除暂停 | 与 IM `1/2/3` 同义 |
| `/flow notify-test` | 自检 IM 与邮件通道，回报实际走的链路 | 排障用 |

> **尚未提供**：`/flow level s|m|l`、`/flow dispatch`、`/flow gate extend`。
> 现在的等价做法是——等级通过 `flow_choose_route` 或门禁的 `level` 参数设置；
> 派单通过 `flow_dispatch_declare` 工具；票据超时后用 `/flow gate release` 解除 hold 再重新决定。
> 这三条命令已列入后续版本，落地前不在文档里冒充"可用"。

## S2 能力

**方案锚点保活**：`.flow/spec.md` 存在时，把它的**摘要便利贴**（路径 / 当前阶段 /
约 600 字摘要 / "去看全文"提示）作为必带上下文注入。内容取自
`<!-- flow:summary -->` 与 `<!-- /flow:summary -->` 之间的块；没有标记就取正文前段。
它走 `required` 运行时上下文，所以上下文压缩后由宿主自动重挂 —— 长任务不会
"忘了自己做到哪"。文件不存在时安静跳过，插件不会替你创建。

**开局四选一**：Flow 模式收到新需求时，模型会调用 `flow_choose_route`，
弹出原生提问框让你选 Plan / Plan Ultra / Build / 暂不执行，AI 推荐项标【推荐】并附理由。
选定后直接完成模式切换（含默认模型与权限），不需要你再敲一次 `/flow`。

**阶段强门禁**：跨大阶段前模型调用 `flow_stage_gate` 停下来让你确认，
三选一：同意切换 / 继续调整 / 先暂停由你接管。只有明确点「同意」才切换，
选另外两项既不切模式也不改权限。规划切实施时把 summary 作为审阅正文呈现，
并可设置「通过后自动压缩一次上下文」（在你的回合结束后、安全空闲时才触发）。

**两个便利命令**：`/flow spec` 看方案文件状态与摘要预览；`/flow compact` 手动触发一次压缩。


## S3 能力：熔断、通知与跨端接管

### 熔断状态机

每个会话键（`session:<id>`，无会话时退化为 `agent:<n>`）维护一份独立状态：

| 字段 | 含义 |
|---|---|
| `streak` | 连续失败次数 |
| `errors` | 最近失败摘要，用于升级时随指令回传 |
| `tripped` / `locked` | 是否已熔断并锁定后续准入 |
| `lastUser` | 最近一次用户指令，供重试与转交复用 |

- **累加**：`tools/post-execute` 观察到失败结果时累加，成功即清零。
- **触发**：达到 `circuit.threshold`（默认 3）时锁定，并在同一批次内完成告警渲染与通知发送。
- **去重**：结算与兜底定时器共享一个完成标记，同一批次只发一次告警。
- **解除**：`/flow retry`、`/flow resume` 清状态；`/flow escalate` 切到诊断模型后重投。

### IM 远程接管 `1` / `2` / `3`

手机端回复单个数字即触发对应动作：

| 指令 | 动作 |
|---|---|
| `1` | 清零连续失败计数，用当前模型重投上一条要求 |
| `2` | 切到 `circuit.rescueModel`（诊断模型），带失败摘要重投 |
| `3` | 解除暂停；后接内容作为新指令下发 |

- 入站文本先剥离 `<dsh_im_source>…</dsh_im_source>` 包装再匹配，避免微信通道的包装前缀导致匹配失败。
- 非数字消息在存在活跃转交时会被转发到目标智能体。

### 单次 Handoff

熔断告警中提示可回复 `3 + 指令`。转交记录带 5 分钟 TTL，**只生效一次**，使用或超时后自动失效，避免指令被重复投放到错误的会话。

### 双通道通知

- **IM / Webhook**：`dsh-im` 渠道或自定义 Webhook（飞书 / 钉钉 / 企业微信 / Bark / PushPlus / 自定义）。
- **SMTP 归档**：定稿或完结事件发送邮件，可携带附件，附件大小受限。
- **事件分流**：按事件类型与渠道开关组合决定推送路径；关闭的渠道不参与判定。
- **自检**：`/flow notify-test` 当场回报各渠道成败与原因（含 SMTP 实际通路）。

## S4 能力：Markdown 提示词库

### 三层优先级

读取顺序固定为：

1. **override**：设置页保存的覆盖文本（存在配置中，不回写磁盘）；
2. **file**：`prompts/` 下的 Markdown 正文；
3. **fallback**：代码内置兜底文本。

任一层为空即回落下一层，缺文件或目录被删除时功能仍然可用。Markdown 读取按 `mtime + size` 缓存，文件改动即时生效，无需重启。

### 渐进式披露

- 只有 `flow` 与 `plan-ultra` 注入子代理目录摘要，其余模式不注入。
- 摘要只包含「谁擅长什么 + 生效路径」，不包含正文；需要时由主控读取对应文件。
- 因此系统提示词体积恒定，且不随子代理数量线性增长。

### Copy-on-Write 防覆盖

| 操作 | 落盘位置 |
|---|---|
| 修改官方子代理 | `prompts/custom/subagents/<id>.md` |
| 新增自定义子代理 | `prompts/custom/subagents/<id>.md` |
| 修改子代理目录 | `prompts/custom/subagents/README.md` |

读取优先级为 `custom/` > 官方目录，`prompts/subagents/` 永不被写入，官方一键更新因此不会覆盖用户改动。删除自定义文件即恢复官方内容。

### 一键更新与防降级

- 主源默认 `https://raw.githubusercontent.com/MeZenith/dsh-flow/main/prompts`，可自定义。
- 拉取 `manifest.json` 后逐文件比对 sha256，只下载变化项；写入采用临时文件 + 重命名，失败保留原文件。
- 路径白名单：仅允许 `base.md`、`modes/*.md`、`subagents/*.md`、`manifest.json`，拒绝 `..`、绝对路径与反斜杠。
- **防降级**：远端版本号更低，或版本相同但 `updatedAt` 更早时整批跳过，回报「远端版本早于本地，已跳过以避免回退」。
- 主源不可达且允许镜像回退时，自动改用 jsDelivr，并回报主源失败原因；关闭回退则直接报错。

### 本地回环接口

仅接受 `127.0.0.1` / `::1`，其余来源返回 403：

| 方法与路径 | 作用 |
|---|---|
| `GET /api/dsh-flow/prompts` | 版本、清单条目、底座与五模式正文及来源、目录、子代理清单 |
| `POST /api/dsh-flow/prompts/update` | 执行一键更新，返回实际源、是否回退、主源失败原因与更新计数 |
| `PUT /api/dsh-flow/subagents/:id` | 写入覆盖层（`id` 需匹配 `^[a-zA-Z0-9][a-zA-Z0-9_-]{0,63}$`） |
| `DELETE /api/dsh-flow/subagents/:id` | 删除覆盖层，官方项即恢复默认 |
| `PUT /api/dsh-flow/roster` | 写入自定义目录 |
| `DELETE /api/dsh-flow/roster` | 删除自定义目录，恢复官方目录 |

宿主未提供 `webServer` 时接口整体跳过，设置页提示改用 `/flow prompts update`。

## S5 能力：v0.5.0 工程级 SOP 编排

### S/M/L 分级矩阵

等级在**开局**由 `flow_choose_route` 的 `level` 参数给出建议，用户可一票升降；之后门禁、`flow:docs` 便利贴、注入文本都读同一份常量（`flow-level.js`），不存在"提示词要五份、门禁只查三份"的漂移。

| 等级 | 适用 | 必做文档 | 人工停点 | 通知节点 |
|---|---|---|---|---|
| **S** | 局部交互改动 / 单点 Bug（≤3 文件、无新模块） | 无编号文档；**必须 1 轮交互形态确认**（点哪里 / 看到什么 / 异常怎么显示） | 1 次 | 不发 |
| **M** | 独立新模块 / 中型功能 | `01` `03` `05` `06` `07` | 2 次 | `03` `05` `acceptance` |
| **L** | 从零建项目 / 架构重构 | `01`–`07` 全套 | 3 次 | `03` `04` `05` `acceptance` |

- **切 Build 前必须齐备**：M = `01 03 05`；L = `01 02 03 04 05`；S 不校验。
- **验收门禁必须齐备**：M/L 都要 `06` + `07`。
- 等级缺省取 `docs.level`（默认 `M`）。

### `.flow/docs/01..07` 与 SSOT

| 编号 | 文件 | 作用 | 通知 |
|---|---|---|---|
| 01 | `01-requirements.md` | 需求：`F-xx` 功能、布局、交互、四态、`N-xx` 不做清单 | **不发** |
| 02 | `02-research.md` | 同类方案 ≥2 候选、许可证、复用/微调/自建结论 | 不单独发 |
| 03 | `03-tech-and-env.md` | 文件级拆分 + **实跑命令环境体检** + 缺凭证三选一 | 邮件/IM 带附件 |
| 04 | `04-ui-spec.md` | Design Token（hex/数值）、8 态矩阵、断点、≥44px | L 级发（含 HTML 原型） |
| 05 | `05-dev-spec.md` | **唯一法典（SSOT）**，冲突必写「覆盖 0X §Y，理由…」 | 定稿门禁 |
| 06 | `06-blackbox-qa.md` | 黑盒：AI 实测（带证据）+ 待人工点验 + `BUG-xx` | 验收门禁 |
| 07 | `07-whitebox-qa.md` | 白盒：`文件:行号` + 触发链 + 四项审计 + 回归点 | 随 06 一起发 |

- `.flow/spec.md` 只放 05 的 ≤20 行摘要（`<!-- flow:summary -->`），两者冲突以 05 正文为准。
- 文档目录 `docs.dir` 默认 `.flow/docs`；`flow_docs_*` 三个工具只允许写该目录与 `.flow/spec.md`，**业务代码始终受只读沙箱约束**。

### 门禁 v2：非阻塞票据

`flow_stage_gate` 不再"弹窗同步等待"，而是**建票即返回**：

1. 返回 `outcome: 'awaiting-user'`，正文里带票据号（`#t3f9`）与 `1/2/3` 选项，并附**强制停手指令**：展示完必须结束本轮。
2. 结算有三个入口，全部走同一个结算器（`gate-settle.js`）：
   - 桌面：`/flow gate answer <票据> 1` 或直接按卡片；
   - 微信/飞书：回 `#t3f9 1 你的意见`（`gate-router.js` 会**掐断 IM 会话自身推理**并把决定与意见原文转给桌面会话）；
   - 超时后迟到回复：同上，票据仍可救回。
3. 超时（`gate.timeoutSeconds`，默认 1800 秒）只做两件事：登记 `expired + hold`、**催办一次**（`gate.escalate`，默认 `both`）。**绝不视为同意**；hold 期间 `flow_docs_write` 与新门禁都会被拦。
4. 关掉卡片 = 没做选择（不是拒绝）：票据保持待决，`/flow gate release` 只解除 hold，仍需你决定。

`kind` 四种形态：`stage`（阶段切换）/ `blocker`（外部阻断求助）/ `acceptance`（人工验收）/ `permission`（写文档授权）。

### 七个新增工具

| 工具 | 关键参数 | 作用 |
|---|---|---|
| `flow_docs_init` | `ids?` `level?` `overwrite?` | 按等级生成缺失骨架（只写模板，**无需授权**） |
| `flow_docs_check` | `ids?` `level?` | 逐份校验存在/空壳/必填章节，缺哪份点名 |
| `flow_docs_write` | `id?` `target?` `name?` `content` `mode?` `deliver?` | 白名单受控写入；`writePolicy=ask` 时未授权返回 `needs-permission` |
| `flow_send_doc` | `docIds[]` `to` `note?` | 按需即时投递：邮件带附件，IM 只发摘要 |
| `flow_ui_skill` | `refresh?` | 探测 taste / impeccable 并给分流建议；未装给**纯对话**三选一 |
| `flow_dispatch_declare` | `assignments[{who,files[],duty?}]` `note?` | 派单声明：探测工具/只读能力/agentPreset，校验白名单重叠，输出 `[调度声明]` |
| `flow_qa_handoff` | `action: brief\|package\|round\|notify\|reset` `project?` | 06→07 简报、06+07 修复包、返工轮次、qa 通知 |

`flow_stage_gate` v2 新增参数：`kind` `level` `docIds` `attachments` `timeoutSeconds` `options` `docId` `toStage` `draftContent`。

### R7 草稿先行

只读会话落盘文档前，必须：

1. 在对话里展示草稿——**≤80 行全贴；>80 行贴「章节目录 + 关键决策 + 风险点」**，完整逐字稿放进 `draftContent`；两档都要求正文结论与 `draftContent` 严格一致。
2. 调 `flow_stage_gate({ kind:'permission', docId, draftContent })`，三选一：`1` 仅本次 / `2` 本会话放行 `.flow/docs` / `3` 拒绝。
3. 获批后才 `flow_docs_write`，写完 `flow_docs_check`。

草稿只进内存与邮件 `.draft.md` 附件，**授权前不写任何文件**；IM 回 `0` 时若磁盘没有该文档，会自动回退读票据里的草稿。

### UI Skills 探测

- 服务名 `skills`，别名归一：`taste-skill | tasteskill | design-taste-frontend → taste`，`impeccable → impeccable`。
- 已装：新页优先 `taste`，老页抛光优先 `impeccable`；两者都有时按"新建 / 改造"分流。
- 未装：给 `1` 装 taste / `2` 装 impeccable / `3` 暂不装用内置规范的**纯对话**选项，不弹门禁、不阻塞流程。
- 设置里关掉 `ui.skillProbe` 后不再扫 skill 目录，直接回内置 `ui-architect` 规范。

### 派单声明与文件白名单

- M/L 进入施工前必须调 `flow_dispatch_declare`，输出固定一行：
  `[调度声明] 派单工具=<tool|none>｜只读能力=<preset|fallback|none>｜模式×特种兵=<n>组｜白名单=<n>段`
- 三条进入施工的路径都会校验：`nextMode:'build'`、`nextMode:'flow'` 且 `docIds` 含 `05`（或在 Flow 下显式 `toStage:'build'`）。**S 级豁免**；`review` 不拦（施工期已声明过）。
- **共享入口禁止划给并发子代理**：`index.js`、`config.js`、`package.json`、`prompts/manifest.json`、`.gitignore`、`cordis.patch.yml`、`README*.md` 由大队长串行接线。
- 白名单相交（相同路径 / 父子目录 / glob 展开后相交）直接拒绝并返回冲突项。
- 没装派单工具时给**诚实降级**：单线程施工、记录"未派子代理"；没有 `read-only` 预设时同样降级并记「未做独立审计」。

### 黑盒 → 白盒双阶验收

1. **第一棒 · 黑盒**（`qa-blackbox`，不看业务源码）：产出 `06` —— AI 自动化实测（每条带证据）+ 待人工点验清单 + 异常边界 + `BUG-xx`。**严禁把没执行的操作写成"已测"**。
2. 有「待人工点验清单」→ `flow_stage_gate({ kind:'acceptance', docIds:['06'], level })`，三选一：`1` 开始验收 / `2` 跳过继续 / `3` 暂停。
3. **第二棒 · 白盒**（`qa-whitebox`，带症状定因）：产出 `07` —— 每条 `BUG-xx` 给 `文件:行号` + 触发链 + 置信度，外加安全 / 并发与释放 / 孤儿模块 / 联动遗漏四项审计；查不到写「未定位 + 取证手段」。
4. `flow_qa_handoff({action:'package'})` 合并成集中修复包（点名未定位与 🔴 Blocker）。
5. **返工上限 3 轮**：每轮前 `flow_qa_handoff({action:'round'})` 计一次，1–3 轮放行，**第 4 轮硬拦**并上报用户；修完只跑受影响路径的轻回归，再交黑盒复验。
6. `flow_qa_handoff({action:'notify'})` 发 qa 通知：正文置顶 🔴 阻塞项与人工点验清单，附件带 `06` + `07`。

本规范面向自行编写子代理提示词的用户，以及协助其配置 `dsh-flow` 的 AI 助手。

### 1. 存放位置与命名

| 项目 | 约定 |
|---|---|
| 目录 | `prompts/custom/subagents/` |
| 文件名 | `<id>.md`，一个文件对应一个子代理 |
| ID 允许字符 | 字母、数字、`-`、`_`，且以字母或数字开头，长度 1–64 |
| 覆盖语义 | 与官方同名时优先使用自定义版本，官方文件永不改写 |
| 更新保护 | 一键更新只同步官方目录，本目录不会被覆盖或删除 |

### 2. 首行识别契约（核心）

**文件第一行必须是：**

```markdown
# <id> | <一句话职责简介>
```

- 设置页「子代理提示词」列表、`Flow` / `Plan Ultra` 注入的子代理目录，都从这一行读取名称与调度依据；
- 分隔符支持半角 `|` 与全角 `｜`，两侧空格可省略；
- 简介建议 10–30 字，写清"擅长什么"，不要重复 ID；
- 首行缺失或格式不符时，列表只能显示 ID，主控也缺少调度依据，因此这一行是必填项。

示例：

```markdown
# mod-dev | 游戏模组开发与资源包构建专家
```

### 3. 推荐四段式正文结构

首行之后建议保持以下四个二级标题，便于主控快速定位：

| 段落 | 内容 |
|---|---|
| `## 身份` | 说明它是执行子代理、只向总控返回回执、不做产品决策 |
| `## 文件边界` | 明确可读与可写的范围，避免越界改动 |
| `## 工作方法` | 编号步骤，写清先查什么、再验什么、如何止损 |
| `## 输出格式` | 回执的固定结构，便于总控直接采信 |

### 4. 标准模板

```markdown
# mod-dev | 游戏模组开发与资源包构建专家

## 身份

你是执行子代理，向总控返回结构化回执。不做产品决策，只交付本领域的结论与产物。

## 文件边界

- 可写：Mods/、Resources/ 下与本任务相关的文件。
- 只读：引擎源码、第三方依赖。
- 需要改动边界外文件时，先在回执中说明理由，等待总控确认。

## 工作方法

1. 先确认目标版本与加载器类型，避免产物不兼容。
2. 复用现有资源管线与构建脚本，不另起一套。
3. 修改后本地构建一次，记录命令与输出。
4. 同一类错误连续失败 2 次即停手，回报已排除的假设。

## 输出格式

```text
## 结论
（一句话，附产物路径）

## 变更
- 文件 — 改动说明

## 验证
- 命令 — 实际输出

## 未验证项
- 未验证内容与所需条件
```
```

### 5. 常见错误

- 只写正文、不写首行 → 列表只显示 ID，主控无法判断何时该调用；
- 首行写成 `# 我的专家`（缺 ID 或分隔符）→ 无法与文件名对齐；
- 在官方目录 `prompts/subagents/` 内直接改 → 下一轮一键更新会被覆盖；
- 正文写成泛化的"请认真思考" → 与底座契约重复，不提供任何领域信息。

## 已知限制

- 模式状态由会话日志里的 `/flow` 命令派生，因此 `fork` 会带过去，但**不会**跨会话同步；
- 权限档位若不在宿主已配置的预设表里（例如默认表没有 `read-only`），
  插件会回退到底层写路径（写 `sandbox/mode` 与 `approval/policy` 事件），
  效果等同，但 `/permission` 芯片上会显示为「自定义」；
- 默认模型会在切换时先做一次可用性校验，校验失败则跳过模型切换并在命令回执里说明，
  不会把会话切到一个不可用的路由上；
- 客户端只引用了 `react` 与 `react-dom`，样式全部使用 `--dsw-alias-*` / `--dsw-radius-*` /
  `--dsw-focus-ring-color` 主题 token，不写入任何字面色值。

## 实现注记（排障用）

- **导出形态**：`index.js` 只能用命名导出。加载器的 `unwrapExports()` 实现是
  `exports.default ?? exports`，一旦写 `export default apply`，插件就变成那个裸函数，
  `Config` / `inject` / `name` 全部丢失，宿主报 `Config: absent`，设置页整条消失。
- **volatile 字段**：`settings.describe()` 用 `volatileForm()` 过滤表单，只保留声明了
  `.volatile()` 的子树，全被丢弃时直接跳过该插件。所以四个顶层字段都标了 volatile；
  代价是读值要走 `config.field.get()`，统一收口在 `plainConfigOf()`。
- **设置页槽位**：`plugins.item` 是"官方插件"卡片位，第三方 bundle 的配置应走
  `settings.section`（每个列表项一个设置页，落在左侧设置导航里）。
